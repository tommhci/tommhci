# Hi, I'm Tom

I build interfaces and tools that make **what a system does not know** visible — where the evidence is thin, where a model is guessing, and where a confident answer is not yet supported.

### Selected work

**[Xu Bing: Epistemic Gallery](https://github.com/tommhci/Xu-Bing-Gallery)** — An interactive exhibition prototype where interpretive difficulty is the content, but losing your way is not. Three formative think-aloud sessions located entry and wayfinding failures; the case study records what changed and what is still untested.  
[Live prototype](https://tommhci.github.io/Xu-Bing-Gallery/) · [Design case study](https://github.com/tommhci/Xu-Bing-Gallery/blob/main/CASE_STUDY.md)

**[AI Control Plane](https://github.com/tommhci/ai-control-plane)** — A Windows/PowerShell reference implementation that makes AI-assisted code changes auditable: project onboarding, protected paths, Git hooks, and repeatable checks. Verified for one integration; explicitly not a production release.  
[Repository and setup](https://github.com/tommhci/ai-control-plane)

**[NRS-1 Workbench](https://github.com/tommhci/nrs-mispricing-workbench)** — An academic prototype that keeps AI and semiconductor narratives separate from engineering evidence, with logged outputs and stated uncertainty. The scoring is experimental, not an investment signal.  
[Repository](https://github.com/tommhci/nrs-mispricing-workbench)

### How I work

Working prototypes rather than decks. Decisions written down with the reason. Results reported with the sample size and the limits attached.

One of these projects is a pre-registered paper-trading test that came back negative at its own stopping rule. I recorded the negative result and stopped, rather than retelling it as a success.
